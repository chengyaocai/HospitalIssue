# 升级说明（增量补丁包）

> 自 v1.0 起，本项目采用**增量升级**策略：后续升级只交付「本次变更的文件」，不再重复打包整个 54MB 部署大包。
> 整包（含 runtime/ 便携 node.exe、node_modules 等）仅在首次交付或结构大改时提供。

## 如何使用增量补丁包
1. 每个补丁包目录形如 `release/hospital-issue-tracker-deploy-patch-vX.Y/`。
2. 包内目录结构与生产部署包一致：`frontend/dist`、`backend/...`，按原层级**覆盖**到服务器对应位置即可。
3. 覆盖完成后：**凡是动了 `backend/src/` 的补丁都必须重启后端服务**；只动了 `frontend/dist` 的补丁无需重启（前端热更新）。
4. 是否需要补跑 `schema.sql`：每个补丁包的 `部署说明.md` 会单独说明；多数情况下代码启动已按 `IF NOT EXISTS` 自动建表 / 加列，无需手工执行。
5. 是否涉及新增权限：每个补丁包的 `部署说明.md` 的「新增权限」一节会说明，请到「系统设置 → 权限」按需勾选/关闭。

## 注意事项
- 部署/升级文档（`.md`）、说明文本（`.txt`）统一为 **UTF-8 带 BOM**，避免记事本打开乱码。
- 启动脚本（`.bat`）为 **GBK/936 无 BOM + CRLF**，因 cmd 按 ANSI 代码页解析。
- `backend/.env` 必须**无 BOM**，否则 dotenv 读取首键会静默失败。
- 服务靠 CWD 定位 `.env`，所有启动脚本须先 `cd` 到 `backend/`。
- 生产访问不通时：先在服务器本机访问 `http://localhost:3000` 分叉排查（能开=防火墙，不能开=服务未监听）。
- 生产升级涉及库结构变更（v1.18 首次访问会自动加表加列），**升级前请先备份数据库**。
